# Teacher lesson builder

Teachers enter through Lessons → Create lesson, opening a new planning conversation directly. The library separates Assigned and Drafts, with title search, class filtering, and direct preview/progress actions. The builder uses a chat-led layout beside a compact editable plan; source and final-task details expand on demand. Four numbered steps group planning, editing, review/preview, and assignment. Drafts and planning conversations are private and autosaved. Planning chat updates the brief; Create draft generates content only after a teacher clicks it. Manual authoring remains available without AI. The chat can also revise one selected stage. A teacher reviews the five instructional moves plus voice/human stakes, visual thinking, and a concrete practice-time budget, previews the actual practice player locally, then assigns an immutable version to one or more of their own active classes.

Images are optional JPEG/PNG/WebP uploads, up to 10 MB and 40 megapixels. The browser scales to 1,800 pixels before transport; the backend independently decodes, strips metadata, scales, and writes WebP into the existing private `original-pdfs` bucket. Image access uses short-lived file tokens issued only after teacher ownership or assigned-student access checks. The AI proposes an editable `imageBrief` for at least one stage: comics, visual metaphors, before-and-after scenes, cutaways, or two perspectives, chosen to reveal the concept. Teachers can use the brief to create an image and upload it. No image generation provider is called by the app; a brief is never presented as a finished image.

## Backend records and operations

All records use the existing server-only `teacher_workspace` collection and teacher ownership. `lesson-draft:<id>` holds the editable brief, conversation, lesson, review and reviewed flag with optimistic revisions. `lesson-version:<id>` holds an immutable content snapshot and teaching review. `lesson-assignment:<version>:<class>` points at a version and carries Shanghai release/due dates. Version identifiers hash the owner, draft ID and lesson content; assigning the same version to the same class is idempotent and preserves its original dates. Revised content creates a separate version and progress key. Old assignments and progress remain intact.

`lessonBuilderLibrary`, `lessonReadBuilderDraft`, `lessonSaveBuilderDraft`, `lessonChat`, `lessonGenerate`, `lessonRefineStage`, `lessonPreview`, `lessonAssign`, `lessonUploadImage`, and `lessonReadImage` are teacher-only learning-content operations. AI operations require a unique request ID and use the existing allowance ledger without automatic paid retries. Server validation gates preview and assignment; assignment additionally requires the teacher's instructional review. All draft edits clear the review in the editor.

Existing `lessonLibrary`, `lessonRead`, practice, final-feedback and reporting operations resolve both the deployed catalog and teacher-owned assignments. Student projections omit answer keys and private rubric guidance. Teacher `lessonRead` includes a preview definition, and teacher attempt mutations are rejected. The frontend preview exercises gates locally and disables final feedback and saving.

## Verification and deployment

`npm test` includes UI authoring tests and `lesson-authoring-checks.mjs` for privacy, conflicts, snapshots, release gates, preview isolation, image decoding and AI failure/allowance behavior. Provider responses are mocked; no paid AI or real student work is used. `npm run build` checks TypeScript and production output.

Deploy `learning-content` with `node scripts/deploy-episode-backend.mjs` before publishing the frontend. The function package includes Sharp for server-side image decoding; the root development dependency makes its tests available in CI. `node scripts/verify-lesson-builder.mjs` uses the existing private deployment environment to verify authenticated library access and private upload storage without writing drafts or reading student work. Existing catalog smoke checks remain in `scripts/verify-lessons.mjs`.

## Engagement and practice

Generation and stage refinement use a clear conversational narrator suited to multilingual high-school readers, a human opening of at most 80 words, and a memorable misconception immediately explained and repaired. Humour targets the situation, not students; sensitive topics use a non-comic mistake. The 10–15 minute plan includes one revision, with at least half the time for doing, comparing and revising. Existing two-check stages, equivalent alternates, missing-move practice and deterministic gates stay in place. Final feedback receives the preceding assessed attempt to ground a specific revision comparison, while preserving the four non-numeric outcomes.

The November 2026 catalog refresh adds 11 original built-in ImageGen illustrations, with literal captions and accessible descriptions. Prompt and file records are in `lesson-engagement-images.json`. The refreshed teacher example uses the same new quotation lesson.

Current catalog definitions have new IDs. Their earlier snapshots, original progress IDs, classes and dates remain in `lesson-catalog-previous.json`. `lessonLibrary` defaults to current lessons; `previousVersions: true` lists the earlier catalog definitions separately. The library checkbox exposes those older lessons to authorized teachers and students, including progress reports and unfinished work. Read and practice requests still resolve the old ID under the original class and release checks; new versions use independent progress keys. When refreshing future catalog versions, append earlier snapshots rather than replacing this history.
